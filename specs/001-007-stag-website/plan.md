# Implementation Plan: 007 Stag Do Website

**Branch**: `001-007-stag-website` | **Date**: 2026-05-15 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-007-stag-website/spec.md`

## Summary

A static, client-side single-page application that serves a 007-themed prank to stag-do attendees. Each route under `/day-{name}` displays a full-screen WebP background; after a ~5 second delay, a centred container fades in containing an embedded YouTube video (default controls, sound on, no autoplay). Day-to-video mappings live in a typed TypeScript config map; unknown day routes redirect to `/day-one`.

Technical approach: React 18 + TypeScript 5 + Vite 5 + TanStack Router (file-based routes). The PDF source asset is converted to WebP once, out of band, and committed under `src/assets/`. Output is a generic static `dist/` bundle deployable to Vercel, Netlify, or GitHub Pages.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode) on Node.js 20+ LTS

**Primary Dependencies**: React 18, `@tanstack/react-router` (file-based routing), Vite 5, `@tanstack/router-plugin` (Vite plugin for code-gen)

**Storage**: N/A — no persistent data; the day-to-video map is a hardcoded TypeScript object compiled into the bundle (per FR-005a)

**Testing**: Vitest + React Testing Library + `@testing-library/jest-dom` for component-level tests. No Playwright / E2E framework — see research.md R9 for rationale.

**Target Platform**: Modern evergreen browsers (last 2 versions of Chrome, Safari, Firefox, Edge) on desktop and mobile; deployed as static assets to Vercel, Netlify, or GitHub Pages

**Project Type**: Client-side single-page web application (no backend, no SSR per FR-006)

**Performance Goals**: Background image visible within 2 s on standard broadband (SC-001); video container fades in at the ~5 s mark with no jank or flicker (SC-002, SC-003)

**Constraints**: No SSR, no auth, no analytics, no runtime config fetch; typed TS config map only (FR-005a); no autoplay (FR-002); single shared layout that scales responsively to mobile (FR-010); no custom error UI when a YouTube video is unavailable (FR-005b)

**Scale/Scope**: 2–5 day routes, single bundled WebP asset, single shared layout/component tree; one-off disposable build for one weekend

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

The project constitution at `.specify/memory/constitution.md` is the unfilled placeholder template — no project-specific principles are defined. Falling back to the global development principles in `~/.claude/CLAUDE.md`:

- **Atomic, single-purpose commits** — the plan decomposes into discrete tasks (scaffold, route, video config, background, fade-in animation, asset prep). Each is implementable as one commit.
- **TDD where the test has real value** — Vitest covers (a) the config-map shape, failing on an invalid YouTube ID, and (b) the video-reveal timing component, failing before 5 s and passing after. Trivial route-glue is intentionally not unit-tested (per the principle's own "skip if only orchestration" carve-out).
- **Twelve-Factor Config** — no secrets needed; the day-video map is application config that ships with the bundle (clarification confirmed hardcoded TS map). No `.env` required.
- **TypeScript safety rules** — strict mode; no `as` casts on unvalidated data (the config uses `as const satisfies …` on a literal, not a cast away from `unknown`); braces on every control structure; static imports only; no `any`.
- **Self-documenting code** — no JSDoc/docstring convention introduced for this fresh project.

No constitutional violations. Complexity Tracking section is intentionally empty.

**Structure Decision**: Single-project SPA (Option 1 from the template). No backend, no separate packages, no monorepo — the disposable single-event scope makes any further split premature. All source under `src/`, tests under `tests/unit/`, generated artifacts under `dist/`. The PDF source asset (`gh-compressed.pdf`) stays at the repo root as the canonical original; the converted `background.webp` lives under `src/assets/` so Vite hashes and bundles it.
