## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies — start immediately.
- **Foundational (Phase 2)**: Depends on Setup. Blocks all user stories.
- **User Story 1 (Phase 3)**: Depends on Foundational. Independently shippable as MVP.
- **User Story 2 (Phase 4)**: Depends on US1's `day.$dayName.tsx` and `__root.tsx` files (it amends them) and on the seeded `days.ts`.
- **Polish (Phase 5)**: Depends on US1 (so there's a real build to verify); US2 nice-to-have for full verification.

### User Story Dependencies

- **US1 (P1)**: Independent — needs only Foundational. Ship as standalone MVP.
- **US2 (P2)**: Builds on US1 by amending three files (`days.ts`, `day.$dayName.tsx`, `__root.tsx`). Cannot be implemented before US1 because the files don't exist yet.

### Within Each Phase

- TDD order in US1: T012 (test) → T014 (impl), T013 (test) → T015 (impl). Each test must be observed failing before its implementation lands.
- T016 (route) requires T014 + T015 (component + config).
- T011 (main.tsx) requires T010 (root route file) so the TanStack Router plugin can generate `routeTree.gen.ts`.

### Parallel Opportunities

- **Phase 1**: T002–T007 are all `[P]` after T001 (different files, no shared state).
- **Phase 2**: T009 and T010 are `[P]` after T008; T011 depends on T010.
- **Phase 3 (US1)**:
  - T012 and T013 (tests) `[P]` together.
  - T014 and T015 (implementations) `[P]` together once their respective tests are written.
  - T016 and T017 (routes) `[P]` together once T014/T015 land.
- **Phase 4 (US2)**: T020 is `[P]` with T018/T019 (different file); T018 and T019 are sequential within their respective files.
- **Phase 5**: T021, T022, T023 all `[P]` (different files); T024 is the manual final check.
